# 正式上线前的权限验收

在独立测试项目创建 GM、玩家 A、玩家 B 和未配置 profile 的用户 C。创建 A、B 各一张卡，A 授权 hp/notes/resources。

- 未登录：不能读取 characters、profiles、rules，不能写入。
- A：只能读写 A 的卡；直接调用 API 读取 B 返回空，更新 B 不成功。
- A：不能修改 name、class_name、level、max_hp、ac、owner_id、editable_fields；即便一并改 owner_id 也拒绝。
- A：资源 current 在范围内可改；name/max、新增删除资源、锁定字段更新均拒绝。
- A：不能通过 profiles 更新 role，也不能创建角色和房规。
- GM：能读写所有角色；修改 owner 后旧玩家不再能读取，新的所有者能读取。
- C：没有 profile 时不能读取规则或角色，也不能写入。
- 两个窗口基于相同 version 保存：只有第一个成功，第二个拒绝并刷新。
- 锁定 hp 后，玩家直接 API 写 hp 仍被拒绝；GM 正常更新。
- 非法 hp / max_hp / 资源值拒绝；有效更新 version 必须增加 1。
- 两个不同账号登录：授权可见的角色和房规变化同步出现，断线后显示状态。
- Auth 注册接口调用被配置拒绝；不仅检查没有注册按钮。
- 手机宽度 375px、键盘导航和表单错误提示可用。
- GM JSON 导出记录条数正确；单独测试项目恢复管理员备份成功。

目前迁移未对真实数据库执行；以上项目应实际验收并记录结果。
