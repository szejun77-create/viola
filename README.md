# 余烬 · 跑团手记 v0.6

React + TypeScript + Vite / Supabase / GitHub Pages。单个私密 DND 3R 房规战役，面向 3–8 人。

## 速查卡公式与来源（最新）

- 六属性：天生＋长效来源＋短效来源，自动合计并显示属性调整值。旧永久/临时非零数据按“原永久调整”“原临时调整”显示为单条来源，新来源保存后不会与旧值重复计入。
- 近战/远程命中：职业基础命中×职业等级求和＋力量/敏捷调整值＋各自长效与短效。
- 强韧/反射/意志：职业对应基础值×职业等级求和＋首级加值＋体质/敏捷/感知调整值＋各自长效与短效。首级加值只看角色第一级的职业，该项基础值为 0.5 时加 1.5，仅一次。
- 本职技能点：各职业（基础本职技能点＋该职业主属性调整值）×职业等级求和＋长效。跨职技能点：各职业基础跨职技能点×职业等级求和＋智力调整值×总等级＋长效。两项均无短效。
- 属性调整值按向下取整((属性总值−10)/2)定义计算；每个项目保留中间小数，只在完整总和最后向下取整，包含长效和短效。HP 也遵循最终取整。十进制贡献采用精确十进制运算，避免浮点误差改变取整结果。
- 防御、接触防御、措手不及防御、擒抱对抗、先攻、伤害减免、法术抗性暂留待配置；移动速度沿用种族定义。

点击任一属性或命中/豁免/技能点的明细，添加、移除或启停来源，保存速查卡调整。GM 在角色档案分别授权六属性长/短效，以及命中、豁免、技能点的长/短效。旧字段授权沿用，不自动开放玩家权限。当前来源仍直接求和，未加入未确认的同类加值叠加规则。

本机刷新即可，旧存档和现有规则不清空。未来真实 Supabase 项目先补齐 `008_stat_effects.sql`。针对性检查：`test:formulas`、`test:stat-sources`；不需要重跑全部测试。

## HP 公式（最新）

速查卡的“生命值 HP”使用：职业贡献＋向下取整((调整后体质−10)/2)×角色总等级＋长效变量＋短效变量。调整后体质沿用天生＋永久＋临时。点击 HP 展开四项贡献，体质仅显示最终 HP 贡献；长效、短效各自展开来源明细。

长效/短效明细可添加名称、正负数值、是否生效；未启用来源不计入。它们作为后续专长、能力和法术模块的数据接入口，本次不增加加值类型叠加算法。点击“保存速查卡调整”保存；GM 在角色档案的权限设置中分别授权长效、短效明细编辑。默认玩家未获授权时只读。

旧角色缺少明细时按空列表（合计 0）处理，保留所有旧数据。本机直接刷新同一地址；未来真实 Supabase 项目需在已有迁移后运行 `007_hp_effects.sql`。本次只验证类型和 HP 专项公式、保存与字段权限，不操作用户实际角色。

## v0.6：角色管理与速查卡

- GM 控制台新增账号对应角色下拉表。每个玩家选一个角色，下拉选择立即保存；转交角色会解除旧关联。创建角色先不分配，随后在表中选择。既有多个角色归属同一账号时先显示提示，不会自动移除旧关联。
- 本机模式从现有角色的 owner_id 保留已有测试账号，支持添加测试账号；登录页可选测试身份，只显示该账号的角色。它仍是演示身份切换，不是密码认证。真实登录继续使用 Supabase Auth；真实 GM 账号列表读取 profiles。
- GM 可在角色管理中删除角色，必须再次确认。网页不能恢复硬删除，请先导出需要保留的记录。删除角色不删除账号或职业配置。
- 新页面“速查卡”紧凑显示已有数值结果、六大属性合计及永久/临时调整。角色档案只留六项天生值；原数据保留，不新增公式。永久/临时调整仍受各自字段授权控制。
- 本机直接刷新同一地址，不用重新录入。不更换存储键。真实 Supabase 项目以后升级时需补齐 `006_assign_character.sql`，为分配提供原子操作；读取、编辑、删除继续沿用已有 RLS 与字段锁定。
- 本次只运行类型检查及专项分配/删除权限测试 `test:assignment`，不修改用户存档，不执行真实角色删除。



## 本次更新：一个职业一个生命数值

GM 登录 → 左侧 **DM 计算配置**。

每个职业只填写一个 **每级基础生命**，不再填写二十行成长表。角色基础生命 = 各职业等级 × 每级基础生命，再求和。例如职业甲每级 10、职业乙每级 4，甲 5 级 → 乙 3 级 → 甲 1 级，总计 `10×6 + 4×3 = 72`。属性调整和特殊能力尚不加入生命。

本职主属性和种族体型、速度配置继续保留。基础命中、强韧、反射和技能点标记待确认，不预设算法，也不沿用旧成长表计算。

**新增职业**：填写新职业名称 → 加入职业列表 → 填写每级基础生命 → 保存职业与种族配置。保存后角色卡的逐级选择立即出现新职业。可随时修改职业名称和生命值；使用稳定标识关联，改名不会破坏既有兼职记录。重复名称不能保存，当前最多 200 个职业；不提供职业删除，以免破坏角色引用。

默认六职业为机关术师、十字军、巫女、战刃、重骑兵、牧师。所有生命值初始为空，未配置显示待配置，0 则表示每级不增加。没有代填实际房规数值。

## 数据保存在哪里

- **连接 Supabase 后**：职业、种族配置保存于 `mechanics_config` 数据表，刷新网页、关闭电脑、更新前端后仍可重新读取和编辑；新职业也在同一数据库。GM 可写、团员可读；保存带版本检查，防止静默覆盖。修改规则后可见角色重新计算。
- **演示模式**：仅保存当前浏览器该地址的 localStorage，不能跨设备同步，清理站点数据会丢失。配置页会明确显示保存位置。
- 正式录入前先接好数据库。现有演示配置不会自动上传到云端；可先导出备份，再在真实项目录入。当前没有网页导入/恢复按钮。
- GM 的“导出记录”包含角色、房规、已保存的职业和种族配置，可留存副本；不含 Auth、profiles、密码和完整数据库结构，不等于完整灾备。

## 角色卡

- 姓名、四种族下拉：人类、强心半身人、幼年灰精灵、修补匠侏儒。
- 按角色总等级逐级选择职业，或连续添加等级段，自动汇总各职业等级。可修改每一级、移除最后一级，最多记录 100 级。
- 六大属性分天生、专长/升级永久调整、装备/魔法临时调整，显示三栏合计。天生默认 10，仅为占位；调整可负，但总值不可负。无属性等效和加值类型叠加算法。
- GM 逐项授权姓名、种族、职业分配与天生值，永久/临时调整各为独立权限组。规则定义仅 GM 可改。
- 旧生命、护甲、资源、备注字段仍保存在数据库与导出中，角色卡及总览不显示。
- 其他人更新会刷新未保存角色表单；其他 DM 的规则更新会替换配置草稿，请及时保存。

## 接入真实 Supabase

1. 创建项目，SQL Editor 按顺序运行迁移。
2. Authentication 中关闭 Allow new users to sign up、匿名登录及其他不使用的登录方式。
3. Auth / Users 手动创建 GM、玩家账号，设置密码并确认用户。账号为邮箱格式；内部标识如 `alice@campaign.invalid` 无法接收邮件，密码重置由 GM 在控制台完成。
4. 管理员在 SQL Editor 添加 profile：

```sql
insert into public.profiles(id, display_name, role)
values ('替换为GM的Auth用户UUID', 'GM', 'gm');
insert into public.profiles(id, display_name, role)
values ('替换为玩家的Auth用户UUID', '玩家', 'player');
```

5. 复制 `.env.example` 为 `.env.local`，填写项目 URL 与 publishable key，重启开发服务。不要使用 secret / service_role 密钥。
6. GM 创建角色，填写玩家 User UUID，设置允许编辑字段。网站内尚无账号创建接口，账号仍由 GM 在 Supabase 控制台创建。
7. 普通窗口登录 GM，无痕窗口登录玩家，验收权限与实时同步。

玩家只能访问分配给自己的角色。规则、职业配置由 RLS 和数据库触发器保护，隐藏按钮不是安全边界。真实项目的 Auth、Realtime 仍须实际验收；本机测试不能替代线上测试。

### 规则模块 / Rule modules

GM 可从顶部「规则模块」打开右侧编辑栏，保存 JSON 定义、声明武器变量、分配角色及设置玩家权限。玩家在速查卡启停获准的模块或输入参数。内置猛力攻击示例默认不分配；完整双语字段与语法表见 [规则模块手册](public/RULE_MODULE_GUIDE.zh-en.md)，网站侧栏也可下载。

本地模式继续使用现有浏览器存储，完整导出含模块定义与角色状态。云端新增迁移 `009_rule_modules.sql` 和 Edge Function `module-state`，玩家模块写入必须通过后端校验；未部署该函数时云端玩家保存会报错。部署前先运行 `python3 scripts/sync-rule-runtime.py`，再按 Supabase 常规流程部署函数，保留默认 JWT 验证。service_role 密钥仅供函数服务端使用。此版没有接入真实 Supabase 做部署测试。

定向校验：`pnpm test:modules`。涵盖表达式限制、加值叠加、猛力攻击、属性影响HP、参数权限、数据库迁移与防绕过保存。

### 被动能力、资源和操作按钮

规则模块新增可选 `mode`、`resources`、`actions`，可在侧栏加载「心似钢铁示例」。分配角色后，在速算卡玩家资源区输入缓冲伤害并点击结算；当前生命与清池原子保存，支持负生命。示例及接口见双语手册第10节。当前生命和原有资源的手动编辑权限可在角色档案的GM权限设置中勾选。云端额外需要迁移010和重新生成、部署module-state；本地无需接数据库。

跨模块引用现支持 `modules.<moduleId>.resources.<key>`、`.params.<key>`、`.vars.<key>`。编辑栏可加载「狂怒反击示例」并查看自动列出的字段路径；同模块多个实例时由GM选择引用来源。用法和公式见手册第11节。本地直接可用；云端需重新部署共享引擎对应的module-state，无需新增数据库迁移。

「定罪示例」新增职业等级变量 `classes.crusader.level`、公式initial、`resourceMode:always`、操作目标`module.enabled`和条件备忘录。次数常驻、增益可关、消耗后不自动回满。完整用法见双语手册第12节；云端需同步重新部署module-state，无需新迁移。

通用防御目标 `defenseCommon` 适用于三种防御；防御基础与盔甲敏捷上限可在GM模块栏配置。援护示例使用 `grant` 向友军发出效果，接收者勾选接受后计算。目标模式支持所有/单个/多个，阵营由GM设置。接口见手册第14节。本地直接可用；云端需迁移011并部署最新module-state，保留其他角色完整档案的原有读取限制。

技能表现按角色保存本职/跨职投入，执行职业累计本职上限和角色等级+3总上限，并分别核对技能点池。DM计算配置可展开职业手工勾选本职技能，也可新增种族。六职业初始对应表见手册第15节；重型武器已按确认映射为攻城武器。云端需迁移012及最新module-state，本地直接使用。

技能现可通过`skills.<id>.ranks/total`等字段读取，能力输出`skill.<id>`提供长效/短效加值。情境限定输出加context标签，技能表单列对应情境合计；不影响通常检定或投入。共效训练门槛为投入≥5，具体对应关系尚待DM提供。完整字段表及说明见手册第17节。

用户提供的54条技能共效现已全局录入：投入≥5，每条固定+2，可累加；23条情境限定项不计入通常检定。多个情境可在技能旁的临时试算区勾选合并。完整清单见手册第18节及public/examples/skill-synergies.csv，规则随mechanics配置备份；云端重新部署共享运行时即可，无需新迁移。
